# デザイン素材の組み込み計画

最終更新: 2026-08-05
状態: D0 決着（**全部切り出し**）。D1 完了。D2 以降は素材の切り出し待ち。

関連資料: [シーン構造](../Architecture/scene-structure.md) / [Game 画面レイアウト案](../GameDesign/game-screen-layout.md) / [ミニゲーム UI 素材](../Specifications/minigame-ui-assets.md)

## 目的

上がってきたデザイン素材を各シーンへ組み込み、仮素材（`UISprite`、無地の色板、文字だけの見出し）を置き換える。あわせて、素材の置き方に起因して発生している難易度選択の当たり判定不具合を直す。

ゲーム進行、タスク寿命、スコア計算、ミニゲームの接続契約は変えない。

この性質から、置き方は 2 通りある。

### 置き方 A: レイヤーのまま置く

Image を `anchoredPosition (0,0)` / `sizeDelta 1920x1080` / `scale 1` で置くだけで、**デザイナーが決めた位置と大きさに正確に出る。** 座標合わせの作業が発生しない。

- 向いているもの: `PC.png`、`PenDisplay.png`、`TitleLogo.png`、`Botton/*`、`Tabu/*`、`HolderPen.png`、`film-noise01.png`
- 代償 1: **透明部分も含めて画面いっぱいの Image になる。** Raycast Target を切らないと画面全体がクリックを吸う。押せる範囲は別の小さい RectTransform で作る。
- 代償 2: 1 枚あたり 1920x1080。**ブラウザ書き出しでのメモリと転送量が効く。** 圧縮設定と Max Size を詰める前提とする。

### 置き方 B: 切り出してから置く

**難易度カード 4 枚はこちらしか選べない。** 4 枚とも「画面中央に 1 枚」で書き出されており（中心が全部 ±50 以内）、そのまま重ねると 4 枚が同じ場所に来る。横並びにするには切り出して個別に配置するしかない。

## 現状の構造

### シーンと素材の対応

| シーン | 背景 | 仮のままのもの |
| --- | --- | --- |
| `Title` | 無地 | 見出しが文字（`TitleLogo.png` 未使用）、START が壊れた配置 |
| `DifficultySelect` | 無地 | カードは配置済みだが**当たり判定が壊れている**（後述） |
| `Game` | `PcOnly/PC` に `PC.png` 適用済み | `TabletOnly/DeviceFrame` が `UISprite`、`DeviceTabs` が `UISprite` |
| `Clear` / `GameOver` | 無地 | 全部 |

`Game` の `MainCanvas` は `PcOnly` → `TabletOnly` → `Shared` の 3 段構成。デバイス枠は各 `DeviceWorkspaceView` の下の `DeviceFrame`。

### PC 開閉アニメーション

`Assets/Anima/` に実体がある。

| 資産 | 中身 |
| --- | --- |
| `Open.anim` | 5 キー / 0.85 秒 / ループなし |
| `clause.anim` | 5 キー / 1.32 秒 / **ループする設定になっている** |
| `PCアニメ1.controller`, `PCアニメ1 1.controller` | 同名に見える 2 つ |
| `sozai/PCアニメ1〜4.png`, `pc４(閉じた状態).png` | 差し替え用のコマ |
| `script/PCAnim.cs` | `Start` で `animator.Play("open")` |
| `Scenes/animationscene.unity` | 動作確認用。本編とはつながっていない |

**このままでは本編に載らない。** 理由が 3 つある。

1. **アニメーションの対象が `SpriteRenderer` である。** 本編の画面は Screen Space - Overlay の Canvas で、Overlay は常に SpriteRenderer より手前に描かれる。UI の `Image.sprite` を動かすクリップに作り直す必要がある。
2. **`clause.anim` がループする。** 閉じ切ったところで止まらず、閉じるアニメが延々繰り返される。
3. **シーンをまたいで見せる必要がある。** タイトル→難易度選択の「開ける」も、ゲーム終了時の「閉じる」も遷移をまたぐ。シーンに置いた実体では遷移の瞬間に消える。

3 については既に前例がある。`FadeOverlayView` が `Resources/FadeOverlay.prefab` を `DontDestroyOnLoad` で常駐させ、`GameFlowController.Transition` から `TryRun(action)` で「暗転 → シーン読み込み → 明転」を包んでいる。**PC 開閉も同じ作りに乗せるのが素直である。**

## 不具合: 難易度選択で右の難易度が選ばれる

### 症状

easy を押すと normal か hard が、normal を押すと hard か endless が選ばれる。easy は**一度も選べない**。

### 原因

カードの絵は 1920x1080 の中に 436x697 しか入っていない。それを 320x76 の RectTransform に入れたため絵が小さくなり、**RectTransform の `scale` を 5 にして大きさを合わせてある。** 押せる範囲も 5 倍になる。

| ボタン | 押せる範囲（画面 x） | カードが見える範囲 |
| --- | --- | --- |
| Easy | -514 .. 1086 | 144 .. 508 |
| Normal | -46 .. 1554 | 590 .. 953 |
| Hard | 354 .. 1954 | 1003 .. 1367 |
| Endless | 808 .. 2408 | 1397 .. 1761 |

**押せる範囲が 1 枚あたり 1600px あり、4 枚が重なっている。** uGUI では後ろの兄弟が手前に描かれ、手前がクリックを取る。並び順は Easy → Normal → Hard → Endless なので、Endless が最優先で x 808 以降を全部持っていく。カードの見た目の位置と一致しない。

### 直し方

`scale` を 1 に戻し、RectTransform をカードの実寸（436x697）にする。そのうえで、

- **切り出し素材が来る場合**: Image をそのまま 436x697 に貼る。
- **切り出しを待たない場合**: `Button` と当たり判定を 436x697 の親に持たせ、絵は Raycast Target を切った 1920x1080 の子として置く。**押せる範囲と描く範囲を分ける。**

どちらでも当たり判定は正しくなる。切り出しが来たら後者から前者へ移せる。

### D1: 難易度選択の当たり判定修正 — 完了

`DifficultySelect.unity` を次の形にした。

```text
EasyButton      275x436.25  ← Button・当たり判定・Diff_Easy.png（440x698 を 0.625 倍）
  MaxScoreText              ← カードの「記録:」の右に配置
  FocusFrame                ← カードいっぱいに広げ、隅の括弧を四隅へアンカー
```

**素材をボタン本体に直接貼っている。** 枠の縦横比を素材と揃えてあるため、押せる範囲と絵が一致する（歪み 0.00%）。

`preserveAspect` は入れない。**入れると、枠だけ変えられたときに「絵は小さいまま、押せる範囲だけ広い」という目に見えない壊れ方をする。** 入れなければ絵が歪むので、壊れたことが画面で分かる。

`MaxScoreText` はカードの中身を実測して合わせた。カード内（440x698）で「記録:」は x 170 で終わり、行の中心は上から 607px、行の高さは 73px。数字の右端は「3分」に合わせて x 400 までとした。

最終的な大きさと位置は手で調整され、**カード 422.7x670.5 / 4 枚で画面の x 53..1882 を占める**形になった。

**PC 画面の内側（`PcOnly/DeviceFrame` = 1221x758 @ -4,-31）からはみ出しているのは意図どおりである。** タスク吹き出しと同じ「画面外の操作」として扱う。PC の画面内に収めると小さくなって読めないためである。D2 で PC 背景を敷いても、カードは縮めない。

記録の表示は数値だけにした。**「記録:」の見出しはカードの絵に描かれているため**、コード側で "BEST:" を足すと二重になる。保存値の読み出しは `HighScoreManager.GetHighScore` に寄せた（キー文字列を各所で組み立てると、片方だけ変えたときに黙って 0 が出る）。

> 経緯: 切り出し前は 1920x1080 の素材を子に置き、押せる範囲だけをボタン本体に持たせていた。
> 切り出し素材が届いたので、その子（`Card`）は削除した。

見出しを y 290 へ、「タイトルへもどる」を y -350 へ寄せた。カードと重ならず、PC 画面の内側に入るためである。

### D6: PC 開閉アニメーション — 完了

**Animator は使わず、コマ送りをコードで持つ形にした。** 理由は 2 つある。

1. **既存のクリップは `SpriteRenderer` を動かすもので、Overlay の Canvas には載らない。** `Image` 向けに作り直す必要があり、どのみち元のままでは使えない。
2. **「再生し終わったら次のシーンを読む」を確実にしたい。** Animator の状態遷移の完了待ちより、コマと秒数を自分で持つほうが素直で、`FadeOverlayView` の作りにもそろう。

**動きは変えていない。** コマの順番と秒数はクリップの実測値をそのまま入れてある。

元の資産（`Open.anim` / `clause.anim` / `*.controller` / `script/PCAnim.cs` / `Scenes/animationscene.unity`）は**消していない。** 控えとして残す。`sozai/*.png` はそのまま使う。**コマは 1920x1080 のレイヤーで、背景の `PC.png` と左右・下端（余白 176 / 183 / 0）が揃っている。**

#### 追加したもの

`Assets/Scripts/Core/UI/PcLidView.cs` と `Assets/Resources/PcLidOverlay.prefab`。`FadeOverlayView` と同じく `Resources` から読んで `DontDestroyOnLoad` で常駐する。**蓋が閉じ切ってから次のシーンを読むため、シーンに実体を置く方式では演出の途中で消えてしまう。**

```text
PcLidOverlay   Canvas(order=900) / CanvasScaler(1920x1080) / CanvasGroup / PcLidView
  Lid          Image  画面いっぱい。コマを差し替える
  ScreenFlash  Image  1221x758 @ -4.4,-30.5（PC の画面領域）。起動の光
```

Canvas の順は 900。**`FadeOverlayView` が 1000 なので、暗転のほうが手前に来る。**

| クリップ | 合計 | コマ |
| --- | --- | --- |
| 開ける | 0.93 秒 | 閉(0.08) → 4(0.20) → 3(0.267) → 2(0.20) → 1(0.183) |
| 閉じる | 1.55 秒 | 1(0.317) → 2(0.316) → 3(0.35) → 4(0.317) → 閉(0.25) |

元のクリップからの違いは 2 点だけである。

- **開ける側の先頭に「閉じた状態」を足した。** `Open.anim` は `PCアニメ4` から始まっており、タイトルに出ている閉じた絵から一段飛んでしまうためである。
- **閉じる側の最後を 0.017 秒から 0.25 秒に伸ばした。** 元の値はループ前提のものである。ループを外したので、閉じ切ったことが分かる間を置く。

#### 遷移との接続

| 経路 | 演出 |
| --- | --- |
| Title → DifficultySelect | 蓋を開ける → 画面が光る → シーン読み込み → 引き上げる。**暗転は使わない**（続けて見せたいため） |
| Game → Clear / GameOver | 蓋を閉じる → シーン読み込み → 引き上げる |
| それ以外 | これまでどおり `FadeOverlayView` の暗転 |

演出が用意できない場合は暗転に戻る。**演出中の再要求は弾く**ので、連打しても二重に遷移しない。

### 差し替えが効く仮組みの条件

**共通フレーム 12 枚が既にこの方式で作られています。** 唯一失敗したのは納品先が食い違った点だけで、
仕組み自体は正しく機能します（発注書 §8）。同じやり方を連打とタイミングにも使います。

| | 守ること |
| --- | --- |
| 画素数 | **発注書の「描く寸法」と同じ**にする（例: `Preview_01` は 1024×1024） |
| ふち | 発注書の指定どおり 9 スライスのふちを入れる（例: `PreviewFrame` は上下左右 48） |
| 縮小率 | **PPU 200**。実寸の 2 倍で描く決まりに合わせる（発注書 §0） |
| 名前と場所 | **発注書のファイル名そのまま**、`Assets/Sprites/InGameUI/MiniGameUI/<区分>/` へ置く |
| 中身 | 白〜グレーの単純な図形。**8 枚のプレビューは番号で見分けられるようにする** |

これを守れば、**本番の絵は同じ名前で上書きするだけ**で取り込み設定も Prefab の参照も引き継がれ、
**差し替え作業そのものが発生しません。**

**Prefab 側では `localScale` で大きさを合わせないこと。** 当たり判定が壊れます。

## 2. フェーズ 1 — 素材を待たずに全部できる

**1-A が他の全部の下地です。** 窓の下地が変われば中身の文字色も配置の判断も変わるため、
先に中身を組むと組み直しになります。

### 1-A. 共通ウィンドウの本素材を繋ぐ

- 本素材は納品済みだが、**納品先がずれて繋がっていない**（発注書 §10 の `Assets/Sprites/MiniGameUI/`
  ではなく `Assets/Sprites/InGameUI/MiniGameUI/` へ届いた）。§8 が想定していた「同名上書きで
  取り込み設定を引き継ぐ」が起きなかった
- 制限時間バーもここに含める。**発注書 §1 に「ゲージに絵は要らない。単色の帯で出す」**とあり、
  今の Unity 標準 `UISprite`（四隅が透明）は指定違反。**新しい絵は要りません**
- 発注書 §10 の納品先を `Assets/Sprites/InGameUI/MiniGameUI/` に直す。
  **これ以降の納品と仮素材の置き場所がここに揃います**

→ [共通ウィンドウの本素材を繋ぐ](2026-08-06-minigame-window-art.md)

### 1-B. 仕分けの本組み

**発注書 §12-1 が「最初に着手するならここ」と名指ししている作業。**
今はカードがメニューバーに重なっており、5 種の中で最も崩れています。

- カードと箱 → **ファイルとフォルダ**の概念へ
- フォルダは 1 種類の絵しか無いので、**フォルダ側だけ色を付けて区別**する
  （ファイルの絵は既に色を持っている: 画像 = 青 / 音声 = 赤 / スクリプト = 緑 / 文書 = 灰）
- 設定は `SortingMiniGame` に持たせる。`GameTuningSettings` / `DifficultyProfile` は
  ミニゲーム固有の値を一切持っていない

→ [仕分けミニゲームの作り直し](2026-08-06-sorting-rework.md)

### 1-C. タイピングの本組み

**発注書 §6 のとおり個別素材が要らないため、これが本組みです。**
今は「残り:」の行がステータスバーの下に潜り、`TargetRomanizationText` と
`AcceptedInputText` が同じ位置に重なっています。

→ [ミニゲームの表示を読みやすくする](2026-08-06-minigame-display-tweaks.md) の §1

### 1-D. 連打の仮組み（+ ファイル切り替えのコード）

**§12-2 のコード変更をここで済ませます。** 5 種のうちコード変更が要るのはここだけで、
**プレビュー画像が本物かどうかとは無関係**だからです。

| | 内容 |
| --- | --- |
| 仮素材 | `Preview_01〜08`（1024×1024・**番号で見分けられる図形**）+ `PreviewFrame`（192×192・ふち 48） |
| Prefab | 空の WorkArea に**プレビュー枠 + ファイル情報**を組む（発注書 §12-1） |
| コード | **1 回押すごとにプレビュー画像とファイル情報（ファイル名・解像度・番号）を差し替える**（§12-2） |
| 表示 | 残り回数を大きく出す（→ 表示の指示書 §2）。**本組みでも中央の要素として残す** |

**ファイル情報の文字列は絵と独立に作れます**（発注書 §3）。本番の絵が来ても文言側は無傷です。

### 1-E. タイミングの仮組み

今は帯だけの状態です。**波形・タイムラインとして組み直します**（発注書 §12-1）。

仮素材 6 枚: `TimelineTrack` / `VideoClip`（128×128・左右 48）、`Waveform_A` `Waveform_B`
（512×128・**左右の端がつながる形**）、`Playhead`（48×192・上下 48）、`CutZone`（96×128・左右 32）。

**波形は横に敷き詰めて使う**ので、仮素材の時点で端をつなげておかないと、
本番の絵に替えたときだけ継ぎ目が消える — という分かりにくい差が出ます。

### 1-F. ミニゲーム中の暗幕を消す

`FocusLightingView` の `dimAlpha` を 0 にするだけ。**Inspector の値 1 つ。**
影の絵への差し替え（`glow`）は素材待ちなのでフェーズ 2 へ。

### 1-G. 小さいものをまとめて片付ける

| | 内容 |
| --- | --- |
| 明るさの段差 | `RoomDimmer`（黒 α0.42）が `Game` にしか無く、蓋を閉じる演出で一段明るくなる |
| `win11Modoki` の縦つぶれ | PC 面で 10.4%（液タブは 1.1%） |
| `DifficultySelectManager` | ロジック専用なのに Canvas 配下で `localScale 2.377` が付いている |
| こだわりポイントの削除 | **使わない決定**。`GameTuningSettings.score.craftPointsDiff1〜3` を消す |
| フォントの欠字 | `架 縁 示 捗 押 違 込 締 憩 怠 緊 絡 択 企 誤 了`。**発注書 §11 が「完了」「誤り」を避けた原因**。アトラスを作り直せば言い回しを戻せる |

**フォント欠字だけは他と毛色が違います**（文字アセットの作り直し）。分けたければ単独 PR で構いません。

## 4. フェーズ 3 — QTE の作り直し（仕様検討中）

**仕様は 2026-08-05 の会話で固まっていましたが、どこにも記録されていませんでした。**
会話ログから復元して [QTE の作り直し](../Decisions/2026-08-06-qte-rework.md) に記録してあります。

要点:

- **`Shift + 英字` の架空ショートカット**を素のキーに混ぜる。**`Ctrl` と `Alt` は使わない**
  （unityroom = ブラウザで横取りされるため）
- **警告ダイアログが次々出て、キーごとに猶予がある。**画面に出ているキーはどれを押してもよい
- **画面に無いキーを押したらミス。**これが無いとキーボードを端から叩くだけでクリアできる
- **位置は固定スロット。**QTE の Prefab は大サイズで透明、中に小ダイアログを並べる

**追加発注は要りません。** 納品済みの 4 枚で組めます。**数値も決まったので着手できます**
（猶予 4.0 秒 → 2.0 秒、総数 3 → 8。`MiniGameCatalog` の制限時間を 12 秒へ上げる作業が付きます）。

**ただし 6 種で唯一ロジックを書き換える作業です**（`QteSequence` は作り直し、テスト 7 件の置き換え）。
他の 5 種の「絵の差し替え」と同じ感覚では見積もれません。

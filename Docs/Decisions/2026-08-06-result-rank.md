# リザルトのランクは達成率で付ける

記録日: 2026-08-06
状態: **仕様確定。未着手**

## 背景

`ResultManager` は難易度・スコア・HP の 3 行を出すだけで、S / A / B / C のランクが無い。
**難易度の数値はこれからプランナー側で調整する**ため、調整で壊れない基準が要る。

## 選択肢

| 案 | 中身 | 却下した理由 |
| --- | --- | --- |
| スコアの絶対値 | 4000 以上なら S など | **難易度を調整するたびに閾値を引き直す**必要がある |
| HP 残量 | 残り HP の割合 | 失敗の回数しか見ていない |
| 複合 | 達成率 + HP + スコア | なぜその評価なのか伝わりにくい |

## 決定

**達成率（捌けたタスク ÷ 出たタスク）で付ける。AI 代行は本来の 50% として数える。**

| | |
| --- | --- |
| 閾値 | S = 95% / A = 80% / B = 60% / C = それ未満。**5 難易度で共通** |
| AI 代行 | **0.5 件ぶんとして数える** |
| Endless | そのまま成立する（時間で割らないため） |
| HP 0 で終わったとき | **ランクを出さない。** GameOver は「もう一度」への導線を主にする |
| 見せ方 | **まず文字だけ。** 絵にするなら 4 枚だが、後から差し替えられる |
| 記録 | 最高ランクの保存は入れない（要望が出れば後から足せる） |

閾値は `GameTuningSettings` に出し、Inspector で調整できる形にする。

## 理由

**達成率の意味は難易度に依らず一定なので、閾値を 5 段階で共通にできる。**
生成間隔・制限時間・タスク寿命をいくら動かしても、ランクの側を直さなくてよい。

**AI を 50% にするのは、丸投げが最善手になるのを防ぐため。**
100% 数えると、スコアが 0.6 倍に減るだけで達成率は満点のままなので、
**全部 AI に投げるのが最も楽に最高ランクを取る方法**になってしまう。
0 にすると AI 依頼という機能そのものを否定することになるため、間を取る。
**スコア側が既に 0.6 倍という重み付けをしている**ので、考え方もそろう。

## 影響範囲

**追加のデータ収集は要らない。** `GameSessionResult` が既に持っている。

| | |
| --- | --- |
| `ResolutionCounts` | 自力成功 / AI 成功 / 自力失敗 / AI 失敗 / 未着手失効の件数 |
| `AiUsedCount` | AI に投げた回数 |

変更するのは `ResultManager`（表示）と `GameTuningSettings`（閾値）だけ。

## 見直し条件

- ランクを絵で出すことにしたとき（素材 4 枚の発注が発生する）
- 「どこまで続いたか」を Endless で評価したくなったとき（生存時間など別軸が要る）

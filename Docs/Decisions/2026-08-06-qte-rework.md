# QTE の作り直し（疑似ショートカット + ダイアログが次々出る形）

記録日: 2026-08-06
状態: **仕様・数値とも確定。未着手**

> **この決定は 2026-08-05 の会話で出たものだが、どの資料にも記録されていなかった。**
> 発注書 [ミニゲーム作業風 UI 必要素材](../Specifications/minigame-ui-assets.md) §7 に
> 「1 つずつ猶予つきで出す形にする」という一行だけが残り、**疑似ショートカット・ブラウザの制約・
> 判定の詰めがすべて落ちていた。** 会話ログから復元してここに記録する。

## 背景

現状の QTE は「表示された並びを左から順に押す」形で、**並びを最初に全部見せている。**
プランナー想定は「次々と入力する文字が出てきて、文字ごとに入力猶予がある」形であり、
**先に出たものから捌く**遊びになる。これはゲーム本体（寿命の短いタスクから片付ける）の縮図でもある。

あわせて「`Ctrl + S` のような PC 操作らしいキー」を入れたいという要望があった。

## 決定

### 1. 入力は「架空のショートカット」にする — **`Shift + 英字` のみ**

| | |
| --- | --- |
| 使う | **`Shift + 英字`**、素の英字、矢印、Space、Enter |
| 使わない | **`Ctrl` 系すべて**、**`Alt` 系すべて**、`Tab`、`Esc`、`F11` |

**理由: 提出先が unityroom（ブラウザ）だから。**
ブラウザが予約している組み合わせはページ側で握り潰せない。`Ctrl+W` `Ctrl+T` は
**タブが閉じる**。`Ctrl+S` `Ctrl+P` `Ctrl+A` は抑止できる場合もあるが、Unity のバージョンと
iframe の状態に依存し、**こちらから検証できない。ゲーム中に保存ダイアログが開けばそのプレイは終わる。**

発注書 §7.4 の「実在ソフトを再現せず、架空のアプリとして表現する」に沿えば、
**ショートカットも架空でよい。** `Shift + S` = 保存、`Shift + Z` = 取り消し。
Shift はブラウザが予約していないので完全に安全で、見た目は組み合わせキーそのものになる。

**画面に `Ctrl` と表示して S だけ押させる案は採らない。** 表示を見た人が習慣で本当に Ctrl を
押してしまい、そのときだけブラウザに持っていかれる。**表示しなければ押されない。**

### 2. 素のキーと組み合わせキーを混ぜる

全部を組み合わせキーにはしない。**抽選で混ざる形にする。**
全部を同時押しにすると指がきつく、難度が跳ね上がるため。

### 3. 出し方 — ダイアログが次々出て、猶予つきで溜まる

- **ダイアログ 1 枚 = 入力 1 回。** デスクトップの上に警告が積み上がっていく絵
- **画面に出ているキーはどれを押してもよい。** 順番の指定はしない
- **キーごとに猶予があるため、自然に「先に出たものから」になる**
- 猶予を過ぎたら、そのダイアログは閉じてミス 1 回

### 4. ⚠ 画面に無いキーを押したらミス — **これが無いと成立しない**

「画面にあるキーならどれでも OK」かつ「無いキーは無視」にすると、
**キーボードを端から全部叩けば必ずクリアできる。**

**`keyPool` のキーを押して、どのダイアログにも当たらなければミス 1 回**とする。
（`keyPool` に無いキーは今までどおり無視）

### 5. 出現中のキーは重複させない

同じキーのダイアログが 2 枚あると、**どちらが閉じるのか分からなくなる。**
そのため**同時に出せる数は `keyPool` の種類数で頭打ちになる。**

→ **`keyPool` は多めに要る。** 疑似ショートカットを混ぜると種類が自然に増えるので、
決定 2 とかみ合う。**素の 4 種だけだと同時 3 枚が限界になる。**

### 6. タイマーは二重になる。圧力は猶予側で作る

`MiniGameBase` が全体の制限時間を持っているので、そこへキーごとの猶予が乗る。
**全体の制限時間は「保険」に下げ、実際の圧力はキーごとの猶予で作る。**
（組み合わせキーを入れるぶん、全体の制限時間は緩和する方針とも一致する）

**猶予の合計が全体の制限時間を超えないこと。** 超えると猶予を使い切る前に時間切れが来て、
**猶予の設定が効かなくなる。**

### 7. ダイアログの位置は固定スロット。抽選しない

毎回位置が変わると**探し直しになる。** QTE は「読んで即押す」ゲームなので、
探す時間が入ると致命的になる。タスク吹き出しで位置を固定したのと同じ理由。

### 8. 窓の構成 — 大サイズで透明、中に小ダイアログを複数

**発注書 §1 の「小 560×280 = QTE のダイアログ」は、ダイアログが 1 枚だった頃の想定。**
複数出すなら、**QTE の Prefab 自体は大サイズで透明**にし、その中に小さいダイアログを並べる。

窓の光も、枠 1 つではなく**ダイアログごとに小さく光らせる。**

**`QteMiniGame.prefab` は 6 種で唯一 `AppWindowFrame` を取り込んでいない**（今も旧レイアウトの
`Title` / `SequenceRow` / `TimeGauge` のまま）ため、共通ウィンドウを剥がす手間は無い。

### 9. 素材は追加発注しない

納品済みの `DialogBody` / `DialogIcon_Warn` / `KeyCell` / `KeyCell_Pushed` の 4 枚で組む。
**キーの状態の違いは着色で出す**（発注書 §7）。ラベルは自由文字列なので「Shift + S」も文字で出せる。

## 影響範囲

**6 種の中で唯一、ロジックそのものを書き換える作業。** 他の 5 種の「絵の差し替え」とは性質が違う。

| | 内容 |
| --- | --- |
| `QteSequence` | **作り直し。** 「並びを左から順に」という前提のクラスなので流用できない |
| `QteMiniGame` | 作り直し（現状 219 行） |
| `QteSequenceTests` | **既存 7 件の置き換え** |
| `QteKeyCell` | 修飾キーの表示に対応。着色の仕組みは流用できる |
| `QteMiniGame.prefab` | ダイアログのスロット配置に作り直し |

## 数値（2026-08-06 決定）

**猶予と総数は指定どおり。出現間隔と同時上限は仮置きで、遊んでから調整する。**
すべて Inspector に出す。

| レベル | 出る総数 | 1 枚の猶予 | 出現間隔（仮） | 同時に出る上限（仮） | 最悪の所要 |
| --- | --- | --- | --- | --- | --- |
| 1 | **3** | **4.0 秒** | 2.0 秒 | 3 | 8.0 秒 |
| 2 | 5 | 3.3 秒 | 1.6 秒 | 3 | 9.7 秒 |
| 3 | 6 | 2.6 秒 | 1.3 秒 | 3 | 9.1 秒 |
| 4 | **8** | **2.0 秒** | 1.0 秒 | 3 | 9.0 秒 |

**「最悪の所要」= (総数 − 1) × 出現間隔 + 猶予。** 全部を猶予ぎりぎりまで放置した場合の秒数。

**出現間隔は猶予の半分にしてある。** こうすると画面に**常に 2 枚**、瞬間的に 3 枚が並ぶ。
間隔を猶予に近づけると 1 枚ずつ順に出る形に、離すと溜まる形になる。**ここが「忙しさ」のつまみ。**

### ⚠ 全体の制限時間を上げる必要がある

`MiniGameCatalog.asset` の QTE は現在 **6 / 7 / 8 / 9 秒**で、
**上の表の最悪の所要（8.0〜9.7 秒）に届いていない。** このままだと猶予を使い切る前に
時間切れが来て、**猶予の設定が効かなくなる**（決定 6）。

**全レベル 12 秒にする。** 保険なので余裕を持たせてよく、タスクの寿命（既定 20 秒）にも収まる。

### `keyPool`（仮・8 種）

素の `W` `A` `S` `D` + `Shift + S`（保存）/ `Shift + Z`（取り消し）/
`Shift + C`（複製）/ `Shift + X`（切り取り）。

**決定 5 のとおり、種類数が同時上限を決める。** 8 種あれば同時 3 枚には十分余裕がある。

## 見直し条件

- **プランナー想定と食い違いが見つかったとき。** この形は「実際のプランナーさんの想定仕様と
  近そう」という前提で組んでおり、直接確認したものではない
- ブラウザ以外（スタンドアロン）でも出すことになったとき。**その場合は `Ctrl` 系が解禁される**

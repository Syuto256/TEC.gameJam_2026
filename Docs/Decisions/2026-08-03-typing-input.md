# タイピングミニゲームの入力判定方針

決定日: 2026-08-03  
対象: 今後追加するタイピングミニゲーム

## 背景

日本語の語句をローマ字入力するタイピングミニゲームを追加する。表示する問題文には漢字を含められる必要があり、同じ読みには複数のローマ字表記がある。

## 決定

- 問題データは、表示用文字列とひらがなの読みを別々に保持する。
- 読みのローマ字変換は、表記ゆれを許容する。初期実装から「し」の `si` / `shi` に加え、「ん」「っ」「きゃ」などの促音・拗音を含む日本語入力に対応する。
- 1 キーの誤入力を 1 ミスとして数える。2 ミスに達した時点でミニゲームを失敗として完了し、対応するタスクを解決不能として取り除く。
- 誤入力では、正しく入力済みの進捗を戻さない。誤った位置から再入力する。
- 誤入力の後、0.2 秒間はすべてのキー入力を完全に無視する。この間の入力はミス数・進捗のいずれにも影響しない。

## 実装上の方針

- 入力途中で複数のローマ字表記候補を保持し、入力がどの候補にも一致しない場合だけミスとする。
- ScriptableObject が持つのは表示用文字列とひらがなの読みだけとする。ローマ字候補は出題のたびに生成し、アセットには保存しない。事前計算はしない（最長のお題でも 3240 通り・1 回だけの生成であり、費用に見合わない）。

## 実装状況（2026-08-04 追記）

この決定どおりに実装されるまでに一度ずれがあった。記録として残す。

本編へ移す際、読みからの変換をいったん省き、`acceptedRomanizations` に**ローマ字を手で並べる**形にしていた。結果、32 問に対して手書きは 47 通りしか無く、生成器が正解とみなす綴り 6332 通りのうち **0.4 % しか通らない**状態になっていた。とくに語中の「ん」を `nn` と打つ人は、`shinnbun` も `kinntaikanri` も弾かれるため、癖の問題として確定で詰んでいた。

手書きゆえの誤りも 14 件あった。すべて長音の「う」を落としたもので（`gakko` `sagyo` `gyomuhokoku` など）、**単語が途中で完成してしまう**誤りだった。`優先順位` の `yuusenjuni` は「ゆうせんじゅに」であり、読みそのものが違っていた。

2026-08-04 に `RomanizationGenerator` を本編（`Overwork.MiniGames.Typing`）へ移し、問題データからローマ字を廃して読みだけにした。手書きの誤りは移行時にすべて解消した。

**綴りを人が持たない、というのがこの決定の要点である。** 書き漏らしは必ず起きるし、遊んで初めて気づく。

## 保留事項

- 難易度ごとの出題数、単語の内容、ミニゲーム制限時間。
- 画面上での入力進捗・ミス・入力無効時間の見せ方と演出。
- 外来語・記号・長音記号（`ー`）を含むお題の扱い。`ー` は `-` として打つ形になっているが、実際の問題でまだ使っていない。

## 見直し条件

実機での入力感確認時に、0.2 秒の無効時間または日本語ローマ字表記の許容範囲が遊びにくさを生む場合は見直す。

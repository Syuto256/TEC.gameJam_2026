# 空グリフを外し、HackGen を Dynamic フォールバックに置く

日付: 2026-08-07
状態: 実施済み

## 症状

`EnkaDotMincho24 SDF` を使うと、一部の文字が**空白**になる。豆腐（□）ではなく、
文字の幅だけ空いて何も描かれない。実例: 「緊急」「企画」「名称」「押す」「締切」。

そのため文言のほうを言い換えて回避しており、発注書 §11 は「完了」「誤り」を避けた表現になっていた。

## 原因

**`EnkaDotMincho24.ttf` に、それらの字の字形が入っていない。**

cmap には登録があるため、TMP から見ると「文字はある」ことになる。
しかし輪郭が空なので、焼いても `glyphRect` が 0×0 になり、幅だけ取って何も出ない。
**これが「豆腐ではなく空白」の理由である。**

該当は **93 文字**。うち改行・空白を除く 90 文字が実害のある字である。

```
§¨°±´¶Α‐‘“”†‡‰′″℃Å⇒∀∂∃∇∈∋√∝∞∠∥∧∨∩∪∫∬∴∵∽≒≠≡≦≧≪≫⊂⊃⊆⊇⊥⌒♀♂♭♯
〇〒〓〔〕ゎ゛゜ヮ仝企怠憩択押捗滅称絡緊締違－／＼＾｀￠￡￢￣ ほか
```

### 調査で 2 度間違えた

**1 度目: 静的アセットの中身を、TTF の実力と取り違えた。**
`HackGen-Bold SDF.asset` を調べて「HackGen も同じ字を持っていない」と結論し、
フォールバック案を却下した。実際は**その静的アセットが限られた文字集合で焼かれていた**だけで、
`HackGen-Bold.ttf` 自体は 93 字のうち **91 字**を持っていた（残り 2 字は改行と空白）。
**アセットではなく TTF を測るべきだった。**

**2 度目: `HasCharacter` で「焼けた」と判断した。**
`HasCharacter` は文字表への登録有無しか見ない。**実体が 0×0 でも true を返す。**
このため「12 字すべて焼けた」と誤って報告した。**`glyphRect` の大きさまで見る必要がある。**

アトラスの広さも疑って 2048 → 4096 に広げたが、**関係なかった**（原因が TTF 側だったため）。
サイズだけ 3.6 倍になったので 2048 へ戻した。

## 決定

### 1. `EnkaDotMincho24 SDF` から空グリフを外す（Static のまま）

**これが要である。** TMP はフォールバックを**「その字が本体に無いとき」しか見ない。**
0×0 の空グリフでも「登録がある」と判断され、本体の空グリフがそのまま使われる。

そこで**実体のある 1463 字だけを残し、空だった 94 字は登録ごと外した。**
これで本体の探索が外れ、フォールバックへ流れる。

**Dynamic にはしない。** Dynamic のままだと、実行時に TTF から空グリフを焼き直して
また登録してしまい、フォールバックへ流れなくなる。EnkaDot の TTF は空グリフを含むため、
この用途では Static が正しい。

> 途中、EnkaDot を Dynamic 化する案を試したが**上の理由で誤りだった。** Static へ戻している。

### 2. `HackGen-Bold Fallback SDF` を新規作成し、フォールバックに登録する

`HackGen-Bold.ttf` から **Dynamic の新しいアセット**を作る（1024×1024 から開始）。
EnkaDot の `fallbackFontAssetTable` へ登録し、90 字を先に焼き込んである
（実行時に初めて出るときの引っかかりを避けるため）。

**フォールバック側が Dynamic であることが効く。** 焼いていない字が来ても、
11MB の `HackGen-Bold.ttf` から実行時に焼ける。

**既存の `HackGen-Bold SDF.asset`（128.9MB・静的 8192 アトラス）は触らない。**
1 つの Prefab が使っているため、そのまま残す。

## 結果（実測）

| | |
| --- | --- |
| `EnkaDotMincho24 SDF` | **Static** / 2048×2048 × 2 枚 / **1463 字（空グリフ 0）** / 16.6MB |
| `HackGen-Bold Fallback SDF` | **Dynamic** / 1024×1024 / 90 字 / 2.1MB |
| **まだ空白になる字** | **0 件** |

探索経路が狙いどおりになっていることを確認した。

```
緊 企 称 押 締 憩 怠 捗 違 絡 択 滅 仝 〒 ♀ ≒ : 本体=False → フォールバックで解決
新 聞                                        : 本体=True  → EnkaDot のまま
鬱 薔 薇 檸 檬 顰 蹙（どちらにも無い字）        : フォールバックが実行時に焼いて解決
```

`EnkaDotMincho24 SDF.asset` は 16.6MB。**コミット済みの版と同じ大きさ**であり、増えていない。

避けていた語がすべて出せることを確認した。

```
緊急 企画 名称 押す 目押し 締切 休憩 怠ける
進捗 連絡 間違い 完了 選択 書き込み 誤り
```

`EnkaDotMincho24 SDF.asset` は 16.6MB。**コミット済みの版と同じ大きさ**であり、増えていない。

## 影響

- **ビルドに `HackGen-Bold.ttf`（11MB）が含まれる。** フォールバックが Dynamic なので元 TTF を必要とする。
  EnkaDot は Static に戻したため、`EnkaDotMincho24.ttf` は不要。
- **フォールバックで出た字だけ書体がゴシックになる。** 実機で確認したところ、
  **明朝の中で若干浮いて見える。** 読めない状態よりは良いという判断で受け入れた（2026-08-07）。
  気になる箇所が出たら、その語だけ言い換えるのが最も安い。
  根本的に直すなら、欠字を含まない明朝の TTF へ差し替えることになる。
- 焼いていない字が初めて出るとき、アトラスへの書き込みでわずかな引っかかりが出る可能性がある。

## 次に同じことを調べるとき

| | |
| --- | --- |
| **アセットではなく TTF を測る** | 静的アセットの文字集合は、その TTF が持つ字とは関係がない |
| **`HasCharacter` を信用しない** | 登録の有無しか見ない。`glyph.glyphRect.width > 0` まで確かめる |
| **空白と豆腐を区別する** | 空白＝字形が空、豆腐＝文字そのものが無い。原因が違う |
| **フォールバックは「本体に無いとき」しか見られない** | 空グリフが登録されたままだとフォールバックへ流れない。`HasCharacter(ch, false, false)` が **false** になっていることまで確かめる |
| **フォールバック元を Dynamic に、本体を Static に** | 本体が Dynamic だと、空グリフを実行時に焼き直して登録し直してしまう |

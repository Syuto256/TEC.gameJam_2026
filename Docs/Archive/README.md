# 保管庫

**終わった作業計画の置き場です。読む必要はありません。**

ここにあるのは、実施済み・撤回済み・方針転換で不要になった計画です。
**現在の実装を知りたいときは、ここではなく [`Architecture/`](../Architecture/) を見てください。**

## なぜ消さずに置いてあるか

計画そのものはもう使いませんが、**「なぜそうなっているか」の調査結果**が本文に残っているためです。
実装を読んでも分からない経緯（当時どこで詰まり、何を測って、何を諦めたか）はここにしかありません。

## 読んではいけない場合

**作業の判断材料にしないでください。** ここの記述は、書かれた時点では正しくても、
その後の決定で覆っているものが混ざっています。実例:

- 発注書 §12 の「素材が届くまで着手しない」は、[統合作業計画](2026-08-06-minigame-overhaul-integrated.md)で
  「仮素材で先に組む」へ**方針転換して撤回**された
- [マージ後の作業一覧](2026-08-06-post-merge-worklist.md)の残項目は、同じ統合作業計画へ**移管済み**

判断に使う資料は次の 3 つだけです。

| 場所 | 内容 |
| --- | --- |
| [`Architecture/`](../Architecture/) | 現在の実装 |
| [`Specifications/`](../Specifications/) | 確定した仕様 |
| [`Decisions/`](../Decisions/) | 合意済みの判断と、その理由 |

## 入れるときの手順

計画が完了したら（あるいは撤回したら）、**その時点でここへ移します。** 後回しにしない。

1. 残す価値のある調査結果を、対応する [`Architecture/`](../Architecture/) の資料へ吸い上げる
2. `git mv Docs/Plans/<名前>.md Docs/Archive/<名前>.md`
3. その計画を指しているリンクを `../Archive/` へ張り替える
